## A3 — activation, boundaries, proportionality

### A3-F1 (critical) — the description has no negative boundary, and the one cheap classification sits behind the 7223-word paywall
`SKILL.md:3` is a pure OR of ~18 triggers with zero exclusions. Requests that match a listed trigger but must not load a 7k-word spec workflow: `npm i -D prettier` and "bump lodash to 4.17.21" (→ "adding or upgrading a dependency"); "add an aria-label to this button" (→ "defining … accessibility … criteria"); "add a TODO, we'll fix it later" (→ "declaring a shortcut or technical debt"); "revert that migration" (→ "rollback"); "fetch my open PRs from the GitHub API" (→ "integrating an external API"). Worst: **"asks to plan before implementing"** — in Claude Code that is a native mode typed dozens of times a day, and it collides with the host's own planning affordance.
The asymmetry is what makes it critical: the Trivial verdict (`SKILL.md:60`, "none — no spec, no plan, no tasks") is only readable *after* paying the full load. **The skill cannot decline itself cheaply.**
Also structurally broken: `SKILL.md:35` makes "Adding a third-party dependency" always-sign-off, `Recorded as` = "the plan's **Dependencies** line, approved with the plan" — but Trivial produces no plan. `npm i -D prettier` either loads 7k words to reach a row whose recording mechanism doesn't exist at that depth, or escalates to Small and buys a spec file for a devDependency.
**Fix:** two sentences in `description`, no body change. (a) size gate: "Use when the change is worth a written requirement (a reviewer could answer 'done or not done?' about it)." (b) explicit exclusions: "Do not use for: a single dependency add or version bump with no behavior change, a one-file fix, a rename, formatting, or when the user has already said what to build and how."

### A3-F2 (critical) — the abandonment cliff: no defined behavior for a user who stops answering, and "just do it" doesn't work
`grep` for `just do it | stops answer | unresponsive | no response | doesn't answer | non-interactive | unattended | headless | autonomous` over SKILL.md + all six references: **zero hits**. The only recovery path requires the user to type a specific sentence (`SKILL.md:19`).
Traced: user says "just do it, stop asking me" at Phase 4 → they are then asked **seven more times** (spec-is-wrong amendment `SKILL.md:168`, declared-shortcut owner+date `:169`, deletion gap `verification.md:50`, removed pre-existing test `verification.md` step 4, and sign-off table rows 2/11/12). The waiver is advertised as an escape and is functionally a speed bump.
Worse is silence: if the user never answers at Phase 2's exit there is **no rule**. An agent following the text correctly halts forever with a `draft` spec and no code. Same for every headless invocation — a subagent, a `-p` run, a CI job, a scheduled agent. Core rule 1 has no fallback for "there is nobody here to approve."
**Fix:** one paragraph after `SKILL.md:19`, **"If no one is answering."** — (a) non-interactive session or no response: write the artifact, mark it `draft`, state in one line what would have been asked, stop cleanly with the artifact on disk; never proceed, never delete. (b) Name **one** class of always-blocking items (irreversible data, shared-environment delivery, deletions) and let the waiver cover everything else — replacing the 12 scattered "a standing waiver does not cover it" clauses with one list. The scatter is what makes the waiver worthless.

## A5 — degraded environments and failure modes (reviewed v2.2.0)

Pattern behind 5 of the 7: wherever the skill needs an escape hatch it **already knows how to write one** ("If the repo uses git…", "With no git and no reliable Files entries…", the ADR "where the project keeps none…" clause, "Documentation and specification artifacts are exempt…") — the hatch is simply missing from the neighbouring rule.

### A5-F1 (critical) — `Base` is mandatory, has no non-git form, and the shallow-clone case lies instead of erroring
`verification.md` → Recording gates: "**Base** — record the base branch this feature starts from and the commit that run measured on (`git rev-parse HEAD` on the untouched tree)… never a bare SHA or `HEAD`". Written as an unconditional imperative with a hard-coded failing command, while the same document has two no-git hatches elsewhere.
- **No VCS:** `git rev-parse HEAD` errors, no branch to name. A required Phase 3 field with no fallback; nothing licenses `— no VCS`.
- **Fresh repo, zero commits:** same, plus `git for-each-ref --no-merged HEAD` errors (that one *is* caught by team-and-review step 4).
- **Shallow clone — the worst, because it doesn't error, it lies:** in a `--depth 1` clone `merge-base` returns nothing or a grafted commit, so Resuming work's rebase test (`merge-base HEAD <Base branch>` ≠ recorded SHA) is **permanently true**. Every resume and every Phase 7 pass diagnoses a phantom rebase, triggers a full re-baseline, and rewrites `plan.md` with a baseline measured at the graft boundary. `git diff <base>...HEAD` in step 6 then fails outright with "no merge base", collapsing the change-set inventory.
Downstream orphans when Base is absent/wrong: Phase 5's confirm-before-first-commit, step 4's base-tree control, step 6's inventory, step 9's `merge-base --is-ancestor`, and the drift check (which has **no** non-git alternative at all).
**Fix:** one clause on the Base bullet — "Where the repo has no VCS, no commits yet, or a shallow history that cannot resolve a merge base, record `Base: — no resolvable history` and note it; every rule that reads **Base** (rebase detection, the base-tree control, the change-set inventory, the integration check) is then skipped, and the report says so." One line retires five silent failures.

### A5-F2 (high) — a config/infra/declarative change cannot converge, and its own deliverable is filed for deletion
Trace: add a Terraform module + k8s manifest. (a) **Phase 1** — `writing-specs.md`'s surface table is UI / API / CLI / Background job / Data pipeline / Library. **No row for configuration or infrastructure**; the agent misclassifies or leaves the surface uncovered. (b) **Step 2** — the project *has* a test runner, so the untestable-by-nature requirement isn't the "no runnable tooling" case; the exception's last sentence ("This exception never applies when tooling exists and the test is merely missing") explicitly excludes it. Verdict capped at *partially met* forever. (c) **Convergence loop** — so the defined terminal state of every infra requirement is "accepted limitation": the workflow records the feature it just shipped as something it could not do. (d) **Step 6** — the `.tf`/`.yaml` files are in the inventory, nothing "reaches" them, and `terraform apply` can't be a recorded gate because Recording gates requires read-only commands. **The feature's entire deliverable is unreached and deletion is the default.**
Step 6 already carries the exemption shape — "Documentation and specification artifacts are exempt from the reachability requirement" — declarative artifacts just were never added to it.
**Fix:** extend that sentence by one clause ("…and so is declarative infrastructure or configuration the project applies through its own tooling — its Evidence is the apply/validate command and the environment it targets, not a caller"), plus one clause on step 2's exception ("…or the requirement's subject is declarative (config, infrastructure, schema) and the project has no runner that asserts it").

### A5-F3 (high) — a context-exhausted session's own committed claim locks it out of its own task for seven days
Phase 5 commits the claim before writing code. Context ends mid-T4. On disk: T4's **Owner** set and committed, T4 unchecked with no note, T4's partial code uncommitted.
Resuming work's integrity check is scoped to **checked** tasks only ("confirm each checked task's work is actually in *this* tree"), so a claimed-unchecked task with real code in the tree is examined by nothing. Then the deadlock: the resume test is literal — **Owner** must equal `—`, not "Owner is someone else" — so the crashed session's own claim reads as held, and it is dated today so the 7-day staleness rule doesn't fire. The resuming agent must skip to T5 out of dependency order into a tree containing T4's partial work, or stop and ask the user who "the branch" is.
Generalisable defect: every durability rule in Phase 5 fires at a *chosen* moment ("before handing the feature over or leaving it, commit it or record it…"). **Context exhaustion is not a chosen moment.** No rule requires in-task state to be durable while it is being created.
**Fix:** one line in the work-present bullet — "A claim whose **Owner** names this session's own branch or user, on an unchecked task with no completion note, is a crashed claim, not a held one: re-run that task's `Verify:` and check its **Files**, then continue it or reopen it — never wait out its 7 days."

### A5-F4 (high) — a repo with an existing requirements practice gets a second, competing source of truth
The ONLY rule in the whole skill touching pre-existing requirement documents is `team-and-review.md` → Discovery: "Existing specs, docs, and commit messages — **the identifiers they cite** show where the team tracks work." An accepted `docs/rfcs/RFC-042-billing.md` with numbered requirements is read for its identifiers and nothing else; its requirements are never read. Phase 1 is unconditional ("Produce `specs/<slug>/spec.md` from `assets/spec-template.md`") and its slug test doesn't recognise an RFC as evidence.
Result: `specs/billing/spec.md` written from the conversation, in parallel with an RFC the team treats as authoritative. Core rule 5 then declares the **wrong** winner ("When the spec and the code disagree, the spec wins" — the new artifact, not the approved RFC), and Phase 7 reports the RFC's own decisions as spec drift.
This is a gap, not a philosophy: Phase 6 already does exactly this integration for *decisions* ("where the project keeps its own decision record… write that entry there too in the project's existing format… where the project keeps none, say so in one line and never start the practice uninvited"). The identical hatch was never written for requirements.
**Fix:** one bullet in Phase 1, before the slug test — "If the repo already holds a requirements document for this work (an RFC, PRD, design doc, or the ticket the **Tracking** line points at), read it first and derive the `R#`/`E#` from it, citing it under Decisions — the same derivation rule as a port feature. The spec restates and makes testable what that document already decided; it never re-decides it, and disagreements with it are `[NEEDS CLARIFICATION]`."

### A5-F5 (medium-high) — one gate table, one baseline set, one "the package": a three-package change verifies one third of itself
Phase 3: "In a monorepo, scope each command to **the package** that owns the code" — singular, definite article with no referent, because core rule 3 has just established the case where "no single package owns the feature". `plan-template.md`'s table is keyed by gate kind, one row each (Tests/Lint/Format/Types/Other): **no package column, no instruction to repeat the table.** Three toolchains (Go/TS/Python) need 3 test commands, 3 linters, 3 type checkers, 9 baselines; the structure holds four. Likely output: one package's gates recorded, and step 4's no-new-failures comparison then runs against a baseline that never observed the other two packages. Doc page also collides — repo-root `docs/<slug>.md` per core rule 3 vs. Phase 6's "follow the project's existing documentation conventions" in a monorepo with per-package docs; no rule resolves it. (The overlap scan is the one monorepo rule that survives contact.)
**Fix:** "In a monorepo, record one gate row per package the feature touches — gate kind plus package, each with its own command and baseline — and scope each command to that package." Plan template's table needs one added column.

### A5-F6 (medium-high) — the base-tree control is unconditional, git-only, and repo-global: it can't run without git and it destroys a concurrent session's uncommitted work
Step 4: "re-run that check on the current tree **and**, always, with the feature's changes removed (stash, or a worktree at the recorded **Base**) — the base-tree control is **never skipped**, whatever the re-run here shows." Strongest always/never in the skill, so nothing overrides it.
- *No git:* both offered mechanisms require git (and the second a resolvable **Base**). An unconditional step with no implementation → every new failure is unattributable and the convergence loop cannot close a pass in a no-VCS repo.
- *Concurrent agents:* `git stash` with no pathspec is **repo-global**. Session B stashes session A's in-progress edits out of the shared tree, runs gates, pops. If the pop conflicts — likely, since A kept writing — A's work is stranded in the stash stack and A has no rule that would ever look there.
Same single-writer assumption upstream: "run each command once on the untouched tree: a tree holding none of *this feature's* work" — "untouched" is relative to this feature only, so a baseline measured while a sibling session's broken uncommitted code is present records that sibling's failure as `pre-existing`, permanently, in `plan.md`. Step 4 handles sibling contamination at verification time; nothing does at baseline time, where it is written to disk and outlives the session.
**Fix:** on step 4 — "Where the tree cannot be reverted (no VCS, or another session's uncommitted work is present), skip the base-tree control, say so in the report, and treat the failure as unattributed rather than new — never `git stash` a tree you did not author." On the baseline bullet — "Confirm the tree holds no other session's uncommitted work before measuring; if it does, record the baseline as provisional."

### A5-F7 (medium) — a stop is a question with no timeout and, in Phase 5, no durable form
The artifact statuses save most cases (an unanswered Phase 3 stop leaves `plan.md` `in-review` and Resuming work catches it exactly; Phase 2's questions survive as `[NEEDS CLARIFICATION]`; Phase 7's gaps are appended *before* approval is sought). **The hole is Phase 5:** "If implementation reveals the spec or plan is wrong, **stop** — go back to the affected phase, amend the artifact with the user" and data-and-delivery's "A command whose target is shared, staging, or production is a stop-and-ask" are pure control flow — nothing is written to disk before the ask. The session ends waiting; on resume the agent sees an unchecked, claimed task with a half-changed tree and **no record that this session already concluded the spec is wrong**, so it resumes implementing against a spec it had already rejected.
Asymmetry showing the fix is already in the skill's vocabulary: an absent *third-party* signer gets a durable state (`pending sign-off: <role>` + "do not start the work it gates"); an absent *session user* gets nothing.
**Fix:** one clause on the Phase 5 stop bullet — "Write the question down before asking it — a dated Decisions entry (or the task's **Notes**) naming what looks wrong and what is blocked — so a session that ends unanswered leaves the stop on disk, the way `pending sign-off: <role>` does."

### A5 verdict
v2.2.0 reasons about *contested* environments carefully (branches, siblings, reviewers, absent signers, stale claims) and about *degraded* ones barely at all. Two defects need a shape change rather than a hatch: **Base** (F1), a single git-shaped field that eight rules read, and the Quality-gates table (F5), single-toolchain by construction while core rule 3 explicitly contemplates features no single package owns. Highest value is F1 — it roots the no-git, zero-commit and shallow-clone failures, and shallow-clone is the only finding here that produces confidently wrong output rather than a visible error.

## A4 — Phase 7 / verification.md, the convergence machinery (reviewed v2.2.0)

### A4-F1 (critical) — a new gate failure is not a gap, and the loop's exit condition never mentions the gates
Step 5 says it when it means it: "Any hit is a gap, same as a failed requirement." **Step 4 never does** — it classifies a failure (`pre-existing`/`flaky`/`new`) and stops. `Handling gaps` routes exactly two inputs (not met/partially met → `G#`; spec drift → user). Exit test at `:71`: "Exit when a full pass yields **met** on every requirement and edge case… with zero new gaps."
Failure: the feature renames a module, a pre-existing `billing.spec.ts` that no `R#` covers now fails, base-tree control passes → classified **new** → no rule turns it into a `G#`. Every `R#` is met, zero gaps filed, exit test satisfied → **the agent reports convergence with `Gates: npm test ❌` printed one line above `Gaps filed: none`.** Same for a new lint error, type error, a11y/size-budget/contract-check failure — every gate class that isn't a requirement's own test. Only `SKILL.md:186` catches it, and Phase 7 hands operative control to the reference.
**Fix:** one clause at the end of step 4 — "A failure classified **new** is a gap: file a `G#` over it and it blocks exit" — and add "the gates show no new failures and the docs are accurate" to `:71`.

### A4-F2 (critical) — evidence is checked for existence and execution, never for sufficiency; the exemplar teaches the cheapest form
`:24` "Find the test that encodes its acceptance criteria. Run it, and read the runner's own report of it…" — everything after "encodes" is about *execution*; **nothing tests the encoding**. The report exemplar `:80` shows what citing costs: `| R1 | met | src/auth/login.ts:42; test login.test.ts ✅ |` — a *file*, not a case; no assertion; no link to the Given/When/Then.
Cheapest verification per verdict, measured from this repo's own runs: (a) **met** = name one green test *file* whose name resembles the requirement — `expect(render).not.toThrow()` satisfies every literal rule in step 2. (b) **met on a re-pass** = copy the previous row — `tests/runs/02-express-crud-api/.../tasks.md:165-170` has **six of ten verdicts reading `| R1 | met | unchanged from pass 1 |`**, and `:71`'s "a full pass yields met" is satisfied by transcription. (c) **met with no test at all** — `tests/runs/01-react-data-table/.../tasks.md:93`: "rendering itself confirmed by manual code-trace", while `npm test` ran fine in that project, so the exception's own guard ("never applies when tooling exists and the test is merely missing") never fired because **nothing checks which branch was taken**.
**Fix:** in step 2 replace "Find the test that encodes its acceptance criteria" with a citation contract — the Evidence cell names the **test case** and the **assertion** encoding the criterion. Add a negative control for the **Minimum shippable** set: the cited test must be shown to fail with the behavior stubbed out. Rewrite the `R1` exemplar at `:80` to match `E1`'s shape at `:83`. Add: "a verdict may not be carried forward from an earlier pass; re-cite or re-run."

### A4-F3 (high) — the six verdicts are neither exclusive nor exhaustive
**Fits two:** `R4` is encoded by a pre-existing integration test that also fails on the base tree. Step 2 → run it → fails → step 3's table gives **not met** → `G4` filed → `:71` refuses exit until the feature fixes an unrelated pre-existing breakage. Step 4, read first, marks the identical failure `pre-existing` and says it "never block[s] convergence". Opposite loop behavior, **no precedence rule**.
**Fits none:** in that second reading there is no verdict value for `R4` at all — `pre-existing`/`flaky` are gate vocabulary and the verdict table has no row for "implemented, its only test is nondeterministic". The agent invents one (empirically **met** with a footnote, because **not met** blocks).
**Second collision:** code that deliberately diverges *and* has no test satisfies **spec drift** and **partially met** simultaneously; they route to different places with unstated precedence.
**Fix:** two rows — **blocked (pre-existing)** and **blocked (flaky)**, each "the requirement's own evidence fails for a cause step 4 attributed outside this change set; reported, not gapped, does not block exit" — plus a precedence line: "spec drift outranks partially met; classify the divergence first."

### A4-F4 (high) — third-party requirements are capped at *partially met* by construction, using a stand-in Phase 3 explicitly blesses
`:30` (Phase 7): "Where the stand-in's shape is asserted by this repo alone, with nothing tying it to the provider's own contract, the verdict is at best *partially met*." `:17` (Phase 3) blesses the list whose **first item is "a hand-written fake"** — which is by definition asserted by this repo alone.
Failure: a Stripe feature records `FakeStripe` on the plan's Dependencies line, the user approves the plan at Phase 3's stop, and Phase 7 caps every Stripe-touching `R#` at *partially met* → a `G#` per requirement → **unclosable by implementation** → pass 2 reproduces them verbatim → the loop only ends via `:71`'s "cannot reach met by any available means, put the choice to the user". Every external-integration feature burns a full extra convergence pass to arrive at a decision Phase 3 already took.

### A4-F5 (high) — the loop has no pass budget and no checkpoint: a pass that runs out of context loses every verdict it produced
The only bound on iteration is advisory: "Two consecutive passes that keep finding new gaps **usually mean** the spec is ambiguous — go back to Phase 2". The skill budgets context for Phase 5 ("Load only the spec/plan sections relevant to the current task") and **forbids the analogue in Phase 7** ("Re-read `spec.md` end to end — not from memory").
The report is written once, at the end (`:101`). ### A4-F6 (high) — the report block has no convergence field and no change-set identifier
